# Doom Loop Detection

Quantized models occasionally get stuck repeating themselves. On a slow edge
device a runaway loop can chew through the entire `max_tokens` budget on a
useless completion. `pipette` watches the live generation and stops it early
when it sees a repeating pattern.

## What gets caught

Six pattern detectors run in order; the first to fire wins. The detector's
name appears in the log line so you can tell which one stopped the sample.

| Detector | Catches |
|---|---|
| `exact_repeat` | Byte-identical repetition: `"\n"` × 500, the same sentence over and over, an outline that loops back to the same headers. |
| `line_repeat` | Consecutive lines that differ only in trivial ways: incrementing counters, drifting timestamps, the same sentence with stray casing or whitespace. (Digit runs, ASCII case, and edge whitespace are normalized away before comparison.) A relaxed length gate (`counter_min_len = 8` vs. the base `min_len = 12`) fires on shorter counter-scaffolded lines like `"740. paradox"`. The digit-run marker distinguishes them from JSON fragments (`},`, `]`), which stay gated. The relaxed-gate path requires a stricter streak (`counter_count = 10` vs. `count = 6`) to avoid false-firing on short legit tables where only a numeric field varies. |
| `cyclic_line_repeat` | Alternating / rotating line patterns at small periods (default 2–16): e.g. a numbered checklist oscillating between `"N. No code block? Yes."` and `"N+1. No object wrapper? Yes."`, or a model rotating through an N-field schema list for hundreds of lines. Uses the same per-line normalization as `line_repeat` and the same `counter_min_len` / `counter_count` relaxed gate, so short cyclic counter loops like `"720. Tunisia" / "721. Egypt" / …` (period 5) are caught once 10 cycles accumulate. |
| `block_repeat` | Large byte-identical blocks (≥ 512 B) written out twice inside the same tail window. Typical case: a JSON-schema block copy-pasted verbatim inside a `<think>` block before the model settles on the final output. |
| `numeric_enumeration` | Runaway integer enumeration: `"*   2"`, `"*   3"`, … `"*   2500"`; short bullet / counter lines whose only variance is a trailing number. `line_repeat` would miss these because the digit-collapsed normalized form (`*   0`, 5 bytes) is too short for its scaffolding-skip gate. Default `count = 40` (so short legitimate numbered lists pass through), and `min_template_len = 3` (so tight-spaced variants like `"* 2"` don't trip it either). |
| `suffix_probe` | Long-period repetition where the prefix drifts but the trailing clause doesn't: `"Wait, I need to check…"`, `"Actually, I'll verify…"`, all followed by the same sentence. |

## What does NOT trigger a stop

- **Same opener, varying body**: every paragraph starts "Wait, the prompt
  says…" but the rest is genuinely different. Too weak a signal.
- **Repetition buried mid-output**: only the tail of the buffer is checked.
- **A loop that just started**: detection requires a few iterations before
  it's confident. Very early loops finish on their own anyway.

## The log line

When a detector fires you'll see exactly one warning line per stopped sample:

```text
doom loop detected by exact_repeat after 4847 generated bytes, stopping early
```

The detector name and byte offset are stable; `grep "doom loop detected"`
across captured logs to count or attribute triggers. That log line is the
only artifact: there's no per-sample field in the result record, no
plan-level summary, no separate subcommand to query.

## Tuning

Each detector has its own settings (a `min_chars` gate plus algorithm-specific
parameters). Defaults come from real eval logs and rarely need changing.

- **One-off override**: pass `--doomloop-<detector>-<setting>` flags to
  `pipette benchmarks run`. **Eval benchmarks only**: they are rejected on
  timing, vl and max-memory cells. `--help` groups them under their own heading
  and lists the flag names. The flags themselves carry no default value: an
  omitted flag inherits the built-in default documented above, so `--help`
  shows the vocabulary, not the numbers.
- **Per-plan override**: add a `[doomloop]` section to the plan TOML.
  Sparse: only fields you set are forwarded; the binary's defaults govern
  everything else.

  ```toml
  [doomloop.line_repeat]
  min_chars = 512   # don't fire on completions under 512 bytes
  count = 4         # tighter trigger; window/min_len stay default
  ```

  A plan with no `[doomloop]` block uses defaults everywhere.

## Extending

To add a new detector, see the rustdoc on `pipette_doomloop::Detector`
(`cargo doc --open -p pipette-doomloop`). It has the trait, the wiring
checklist, and a compilable example.
